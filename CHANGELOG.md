# Changelog

All notable changes to the DSOEnhanced Jenkins Shared Library are documented in this file.

## [Unreleased]

### Changed
- The Nexus delivery is one service, `NexusDeliveryService`. The snapshot of stage 6 is published under one tag per run, `<BUILD_NUMBER>-<yyyyMMdd-HHmmss>` in UTC, shared by every service of the run and written to `build.tag`, which the security pipeline archives and the extended pipeline copies with `pipeline-config.yaml` and `release-gate.json`.
- The snapshot is described under `delivery.push`: `delivery.push.maven` (goals and the artifacts by file name, extension and classifier) and `delivery.push.gradle` (repository, group, artifact and the artifacts to publish). A Gradle service publishes the matched files with its own wrapper on a generated project in the temporary folder of the build (`resources/com/bbh/devsecops/nexus-delivery.gradle`), which is removed afterwards. The earlier `delivery.maven` with `build.buildPath` still works. A Gradle service without `delivery.push.gradle.artifacts` is not required in stage 6 and its UrbanCode versions keep the build number.
- `delivery.nexusDeliveryEnabled` of a service wins over `deploy.<target>.rd.nexusDeliveryEnabled`, and every console line names the setting that was read.
- The extended pipeline deploys a VM service to the lower test region with UrbanCode Deploy (DOD), as the full pipeline does; the component versions carry the tag of `build.tag`, otherwise the build number.
- The deployment repository of an OpenShift service (`deploy.openshift.rd.deploymentPath`) is checked out in the Monitor stage, without switching the current service; the SAST scanning and Nexus IQ GoldenFix pipelines leave it out.
- The release delivery (stage 12) pushes the NuGet package of a .NET service with `delivery.nuget.source`. For every other build tool the release delivery of the safe artifact is not implemented yet: the service is not required with a `[NEXUS]` line and the snapshot of stage 6 stays the delivered artifact. The stage no longer runs `./gradlew publish` or `mvn deploy`, and the extended pipeline runs the Node.js build only before a release delivery that is available.
- The `artifact_version` of the `build_evidence` point is the tag that the service delivered, otherwise the pinned `rd.buildTag` or the build number.
- SAST runs through the HCL AppScan on Cloud REST API v4: SAClientUtil only generates the IRX, which is uploaded (`FileUpload`) and queued (`Scans/Sast`) with `curl` (`curl.exe` from a batch step on Windows agents); the status is polled and the HTML and PDF reports are generated and downloaded through the API. The reports and the severity counts leave out the issues with the `Noise` status.
- SAST and DAST of every service sign in with the one API key of the functional AppScan on Cloud user, `asoc.keyId` and the Jenkins Secret text credential named in `asoc.token` of the library defaults (`resources/com/bbh/devsecops/defaults.yaml`). A service sets only its `appId`; a `keyId`, `token` or `credentialsId` under `asoc`, `sast` or `dast` of a service is ignored with a `[WARN]` line that names it, and a service without a key ID no longer stops the build at the start.
- The run signs in once and reuses the bearer token for SAST and DAST, signing in again after 90 minutes. The sign-in body is written to the temporary folder of the build and removed after the call, and the `curl` calls run without shell tracing, so neither the key secret, the bearer token nor the proxy password reaches the console. The proxy password is read from `proxy.pass` when `PROXY_PASS` is not set.
- GoldenFix changes only the last number of a version (the patch): `1.2.3` may become `1.2.4`, never `1.3.0`. The fallback to a minor or major upgrade when Nexus IQ offers no patch version is removed; such a dependency is left untouched. Pre-releases are never proposed, and every manifest applies the rule to the version it declares.
- GoldenFix proposes only direct dependencies: `goldenFix.onlyDirectDependencies` is removed. `overrides`, `resolutions` and `constraints*.txt` are changed only for components that Nexus IQ marks as direct.
- The GoldenFix pre-check build is mandatory: `goldenFix.verify.enabled` is removed, and a change that no build can verify ends `NOT_VERIFIED` without a pull request.
- The GoldenFix pre-check runs the unit tests of the project with the proposed versions: `mvn -B -q test`, the Gradle `test` task, `npm test` (with `CI=true`, when `package.json` has a `test` script other than the `npm init` placeholder), `pytest` in a temporary virtual environment after a real `pip install`, `flutter test` or `dart test` when a `test` folder exists, and `dotnet test`. A failing test lowers the versions like a failing build. Windows agents get PowerShell forms of every check; a .NET project built with the classic `MSBuild.exe` is still built without its tests. `goldenFix.verify.commands` still replaces the check of an ecosystem.
- The shared version catalog repository is verified before its pull request: its own build, or the application built with the changed catalog files; otherwise no pull request is raised there.
- A dependency left untouched because Nexus IQ offers only a minor or major upgrade is listed in the report and in the metrics under the upgrades that were not applied automatically, with the version Nexus IQ offers.
- The full and security pipelines run the unit tests, Nexus IQ, SAST and SonarQube at the same time, as parallel branches of the stage *Static analysis*, and the full and extended pipelines run the regression, smoke and performance tests and DAST at the same time in the new stage *Dynamic analysis*. Both are the default: `staticAnalysis.parallel` and the new `dynamicAnalysis.parallel` default to `true`, and `false` in any service, or `DSO_STATIC_ANALYSIS_PARALLEL`/`DSO_DYNAMIC_ANALYSIS_PARALLEL` set to `false`, runs the stages one after another as before. Windows agents keep the static stages one after another.
- SAST compiles and queues its scans in a copy of the workspace (`<WORKSPACE_TMP>/dso-sast-workspace`), which is removed after the queue, so its compile never changes the files the other branches read; SonarQube of a service waits until the unit tests of the services of its source folder have written their coverage. When the copy cannot be made, the run logs a `[WARN]` line and falls back to SAST queuing first while the other three run one after another.
- A value of `staticAnalysis.parallel`, `dynamicAnalysis.parallel` or their environment variables that is neither `true` nor `false` no longer counts as `false`: the console names it in a `[WARN]` line and the default `true` is used. A value equal to the default is named in an `[INFO]` line, so that it can be removed.

### Fixed
- Several services of one run no longer overwrite each other's `build.tag`: the tag is created once per run, and the delivered version is no longer written over the `delivery` section of the run state.
- DOD hands the absolute base directory of a component to UrbanCode Deploy.
- The OpenShift image build finds the artifact with `find` when it is not under `build.buildPath`, renames `baseArtifactName` wherever the build left it, copies each file of `deploy.openshift.rd.addFile` only when it is set (no more `cp null`), prints the build path and artifact names, and builds or copies no image while Nexus delivery is disabled.
- C# / .NET coverage now reaches SonarQube: `dotnet test` (and `vstest.console` with Coverlet) collects `XPlat Code Coverage;Format=opencover`, so `coverage.opencover.xml` is read by both the pipeline report and `sonar.cs.opencover.reportsPaths`. `coverageTool: cobertura` stays available for the report only and logs a `[WARN]` that SonarQube cannot import it for C#.
- The .NET settings `build.dotnet.mode`, `useDotnetCli`, `tests.unitTests.dotnet.runner` and `coverageTool` are validated by one class (`DotnetOptions`), so the auto-resolve and the build runner accept the same values and log the same `[WARN]` fallback.

### Added
- The console and the box *Parallel stages* of the pipeline report show, for each group of stages that ran at the same time, the time one after another, the time in parallel and the time saved.
- The table *Manual actions vs DevSecOps Automated Actions* at the bottom of every pipeline report compares, recalculated on every run, the time of the steps of the run done by hand with the time the pipeline took: Code Build Trigger, Unit Test + Code Coverage, SAST + Nexus IQ + SonarQube, Deploy lower test region and Regression + Smoke + Performance + DAST, with the totals and the time recovered by the run. The minutes of the manual steps are `report.manualEffort` of the library defaults (10 minutes to start each build, scan, deployment and test, 360 minutes for a DAST by hand).
- The stage *Download artifacts from Nexus Repo* of the extended pipeline, before the lower test region deployment: `delivery.pull` downloads the snapshot named in `build.tag` into `delivery.pull.outputDirectory`, with Gradle (`delivery.pull.gradle`) or with Maven `dependency:get` and a copy from the local repository. It is not required for an OpenShift service, without Nexus delivery or without `delivery.pull`, and it fails when `build.tag` is missing.
- Every setting the auto-resolve fills in or corrects is recorded per service: the log prints `[INIT] Auto-resolved for <service>: <setting> = <value> (<why>)` and the pipeline report shows the *Auto-resolved settings* card.
- **C# and .NET Build Tool & Ecosystem Support (Windows Classic MSBuild + NuGet & `dotnet` CLI Override)**:
  - Full first-class support for C# / .NET repositories via `buildTool: 'dotnet'` (and aliases `msbuild`, `csharp`, `.net`), auto-detected from `*.sln`, `*.csproj`, `*.fsproj`, `*.vbproj`, `Directory.Packages.props`, `Directory.Build.props`, `packages.config`, and `global.json` in both `BuildService.detectTool()` and `RepoStackAutoResolver`.
  - Classic Windows Jenkins agent default via `DotnetBuildRunner`: executes `NuGet.exe restore` and `MSBuild.exe` (`/t:Build`, configurable solution/configuration/platform/flags) with unit testing via `vstest.console.exe` (`/Logger:trx`) and optional `OpenCover.Console.exe`, plus optional override (`useDotnetCli: true` or `mode: dotnet`, also default on Linux) for `dotnet restore` / `dotnet build` / `dotnet test --collect:"XPlat Code Coverage"` / `dotnet publish`.
  - Unit test result ingestion (`BuildService.reportUnitTests`) for Visual Studio TRX (`**/TestResults/*.trx` on Windows PowerShell & Linux Python) as well as JUnit XML, recording exact passed/failed/skipped counts into `PipelineState`, `PipelineMetrics`, and Jenkins `reportUnitTest`.
  - Multi-report code coverage support for **Cobertura XML** (`coverage.cobertura.xml`) and **OpenCover XML** (`coverage.opencover.xml`) across both Linux (`CoverageReports` Python scanner) and Windows (`BuildService.legacyCoverage` PowerShell XML parser), displayed in the HTML report `Code Coverage` card and table.
  - SonarQube integration (`SonarService.scanDotnet`): executes the 3-step SonarScanner for .NET lifecycle (`SonarScanner.MSBuild.exe begin` -> MSBuild -> `end` by default on Windows, or `dotnet sonarscanner` override) with auto-discovered `sonar.cs.opencover.reportsPaths` and `sonar.cs.vstest.reportsPaths`, plus fixed `Authorization: Bearer` header in Windows `fetchIssueCounts`.
  - HCL AppScan SAST (`AppScanService.generateIrx`): supports pre-IRX MSBuild / `dotnet` compilation on both Windows and Linux agents, clean Windows `robocopy` staging even when `includedDirs` is omitted, and cross-platform error log handling.
  - Cross-platform Nexus IQ GoldenFix & Security PR support for the **`nuget`** ecosystem (`NugetUpdater` updating `*.csproj`/`*.fsproj`/`*.vbproj` `<PackageReference>`, `Directory.Packages.props` `<PackageVersion>`, MSBuild `$(Property)` groups in `Directory.Build.props`, and classic `packages.config`, pre-check builds in `ManifestBuildVerifier`, Windows PowerShell Git worktree/push in `GitSourceRepository`, and Windows `curl.exe` in `RestClient`).
  - NuGet package delivery (`delivery.nuget` via `nuget.exe push` / `dotnet nuget push`), Windows UrbanCode Deploy file verification, complete `examples/DotNetApp/` configuration, and updated documentation.
- **Liquibase (SQL / PL/SQL) Build Tool Support (Single-Module & Multi-Module / Polyglot)**:
  - Full first-class support for database migration and PL/SQL / T-SQL / SQL services via `buildTool: 'liquibase'`.
  - Auto-detection of Liquibase services in `BuildService.detectTool()` through `liquibase.properties`, `changelog.xml`, `changelog.yaml`, `changelog.yml`, `changelog.sql`, `db/changelog/db.changelog-master.xml`, or `db/changelog/db.changelog-master.yaml`.
  - Cross-platform command execution (`BuildService.runLiquibaseCommand`) supporting both Linux/macOS (`sh`) and Windows (`bat`), `dir` working directory overrides, and custom `env` variables.
  - Configurable build commands (`build.liquibase.commands`, default: `validate`) and arguments/flags (`build.liquibase.flags`, e.g. `--changelog-file=...`).
  - Unit tests / changelog validation stage (`tests.unitTests.liquibase.commands` and `flags`), skipping gracefully when no validation commands are configured.
  - Automatic code coverage bypass: database changelog projects without test coverage reports bypass the 60% coverage gate in `BuildService.checkCodeCoverage()` without failing or marking the stage unstable.
  - SAST AppScan support: Java bytecode compilation (`doCompile`) is skipped by default for Liquibase services, while optional pre-IRX Liquibase commands (`asoc.liquibase.commands` / `tasks` and `flags`) are supported and tracked by `BuildUtils.hasCustomSastCompile()` (`sastCompileOverrides`).
  - SonarQube analysis for SQL / PL/SQL (`SonarService.scanLiquibase`): invokes `sonar-scanner` directly with `-Dsonar.sources` (defaulting to `tools.sonar.liquibase.dir`, `build.liquibase.dir`, or `sourceDir`), custom `tools.sonar.liquibase.flags` (e.g. `-Dsonar.plsql.file.suffixes=.sql,.pks,.pkb`), `dir`, and `env` without invoking Java build runners.
  - Optional JDK configuration: `javaPath` is exported as `JAVA_HOME` when specified, while omitting `javaPath` and `buildToolAutoSetup` does not halt Liquibase services.
  - Seamless multi-module / polyglot support: Liquibase SQL / PL/SQL services can run in the same pipeline alongside Gradle, Maven, Java, Kotlin, Node.js / Angular (`build.node`), Python / pip, and Flutter modules.
- **Multi-Report Code Coverage (`CoverageReportScanner`)**:
  - Automatic discovery of all JaCoCo XML (`jacoco.xml`, `jacocoTestReport.xml`, Android `reports/coverage`, Kover `reports/kover`) and LCOV (`lcov.info`, `*.lcov`) reports across all workspace subdirectories (`build/`, `target/`, `release/`, and module folders).
  - Duplicate and aggregate report detection (`report-aggregate`, `testCodeCoverageReport`), counting uncovered module classes from aggregate reports when needed.
  - Per-report breakdown table in the HTML pipeline report and equal-weighted service mean calculation for multi-module and full-stack (Java + Node.js/Angular) services.
  - Fallback report resolution for Windows agents and environments without `python3`.
- **Modern Configuration Discovery (`devsecops_config.yaml`)**:
  - Native loading of `devsecops_config.yaml` as the primary repository configuration file with automatic fallback to `config.yaml` when running without a portal key.
- **Parallel Static Analysis (`staticAnalysis.parallel`)**:
  - Support for `staticAnalysis.parallel` in global defaults / service config and the `DSO_STATIC_ANALYSIS_PARALLEL` environment variable override.
  - Queues HCL AppScan SAST scans for all services first, removes staging directories (`appscan-source-staged`), runs Nexus IQ (with GoldenFix) and SonarQube while AppScan analyzes in the cloud, and polls SAST results last.
  - Automatic fallback to sequential execution when a service on Linux/macOS defines custom `asoc.gradle`, `asoc.maven`, or `asoc.liquibase` compile commands that differ from its `build` commands.
- **Node.js Pre-Build (Stage 0, `NodeBuildService`)**:
  - Optional Stage 0 (`build.node.enabled: true`) for frontend builds (`npm ci`, `npm run build`) before backend Gradle or Maven compilation, SAST compilation, Nexus IQ GoldenFix builds, and Extended pipeline release delivery.
  - Supports `build.node.dir`, `commands`, `installationName`, `nodePath`, `registry`, `npmrcCredentialsId`, `env`, `timeoutMin`, and automatic addition of `<dir>/package-lock.json` to Nexus IQ scan patterns (`nexusIqScan: true`).
  - Automatically excludes `node_modules` from AppScan SAST IRX archives after a Node.js build.
- **Nexus IQ GoldenFix Shared Version Catalogs (`goldenFix.versionCatalogs`)**:
  - Automatic discovery and updating of Gradle version catalogs (`*.versions.toml`, `settings.gradle(.kts)` `versionCatalogs` blocks, `apply from:` scripts, `java-platform` modules) and Maven parent/imported BOM POMs, plus explicit paths/globs in `goldenFix.versionCatalogs`.
  - Single shared branch and pull request (`PR_CREATED` / `PR_UPDATED`) across all services in a multi-module repository, preserving highest target versions across modules.
  - Multi-ecosystem pre-check verification across Maven, Gradle, npm (with automatic `package-lock.json` refresh), pip (`requirements*.txt`, `pyproject.toml`), and Flutter/Dart (`pubspec.yaml`).
- **Service Configuration & Deployment Enhancements**:
  - Support for `deploy.vm.rd.nexusDeliveryEnabled: false` and `deploy.openshift.rd.nexusDeliveryEnabled: false` to disable Stage 6 Nexus snapshot delivery and deploy pinned OpenShift `buildTag` images.
  - Custom AppScan SAST scan naming via `sast.scanName`.
  - Support for `tools.sonar.badgeCredentialsId` (Jenkins Secret text credential) as a secure alternative to plain-text `tools.sonar.badgeToken`.
- **Standalone Library Distribution (`DSOEnhancedWithoutPortal` branch)**:
  - Maintained in parity on `DSOEnhancedWithoutPortal` as a standalone "Version 0" shared library with zero portal integration, operating purely via `Jenkinsfile` (`projectNames`) and `devsecops_config.yaml` / `config.yaml`.
